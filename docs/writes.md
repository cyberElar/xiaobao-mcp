# 作业写入与文件上传

服务提供 6 个写入工具，以及只读的 `get_write_capabilities`。先确认平台、作业和文件，再调用相应工具。校宝与 Teams 使用不同的账号绑定和作业 ID。

## 授权

MCP 写入需要同时具备 `schoolis.read` 和 `schoolis.write`。现有只读令牌继续只读。客户端应按工具的 OAuth 提示重新授权；刷新令牌不能扩大原授权范围。

微软接口还需要独立的上游权限：

| 操作 | 微软委托权限 |
| --- | --- |
| Teams 提交、撤回、准备资源目录和关联附件 | `EduAssignments.ReadWrite` |
| Teams 附件文件上传 | 另外需要 `Files.ReadWrite` |
| 创建 Outlook 事件 | `Calendars.ReadWrite` |

运行 `npm run microsoft:login -- --write` 可通过手机申请这些权限。应用和学校策略可能要求管理员同意。已有作业写权限不表示已有文件写权限。

`get_write_capabilities` 返回当前 MCP 是否具备写入授权、校宝连接状态，以及微软作业、日历和文件写权限。这些状态不能保证某个作业允许提交；写入工具还会检查作业与提交状态。

## 文件输入

两个上传工具每次只接受以下一种输入：

- `file`：ChatGPT 传入的文件对象，包含 `file_id`、`download_url`，可附 `file_name` 和 `mime_type`。
- `text`：服务器编码为 UTF-8 文件的文本。
- `contentBase64`：标准 base64 文件内容，不含 `data:` 前缀。

使用 `filename` 指定文件名。未提供时，服务使用 `file.file_name`。文件名不应包含路径、控制字符或系统保留字符。

单个文件最多为 5 MB，空文件会被拒绝。ChatGPT 文件通过 HTTPS 下载；支持 `oaiusercontent.com` 和 `usercontent.openai.com` 及其子域。下载不发送校宝 Cookie 或微软令牌，不跟随重定向。服务不接受本机文件路径或任意网站地址。模型无法取得原文件内容时，不应编造 base64。

文件内容只用于上传，不执行，也不保存在本机文件目录。工具返回文件名、大小和 SHA-256，可用于核对上传对象。

## 校宝作业

1. 调用 `get_assignment_detail`，核对作业、现有回答和附件。
2. 需要新增附件时，调用 `upload_assignment_attachment`，保存返回的 `uploadReceipt`。
3. 调用 `submit_assignment`，传入同一作业 ID 和所需附件凭据。
4. 检查提交响应中的 `accepted` 和 `verification`。

上传只生成待提交附件，不会自动交作业。上传凭据通过签名绑定账号和作业，有效期为 7 天。调用方不能把任意文件 URL 当作提交附件。

`submit_assignment` 省略 `remark` 时保留现有回答。`keepExistingAttachments` 默认为 `true`，在现有附件后添加新附件。将其设为 `false` 会用本次附件列表替换原列表。最多提交 30 个附件；回答和附件都为空时停止。

服务只接受未提交或允许重新提交的作业。已关闭、已批改、批改中及外部 LMS 作业不进入提交流程。已提交作业重新提交前，服务读取学校的继续回答开关。

学校返回业务成功后，服务尝试重新读取详情，返回状态、回答匹配结果和附件数量。回读失败时，`accepted=true` 与 `verification.checked=false` 表示请求已被接受，但未完成确认。应先查询状态，不应直接重复提交。

## Teams 作业

1. 调用课程、作业和提交查询工具，取得本人的 `classId`、`assignmentId` 和 `submissionId`。
2. 需要附件时，调用 `upload_teams_attachment`。
3. 核对关联的附件后，单独调用 `submit_teams_assignment`。
4. 需要撤回时，调用 `unsubmit_teams_assignment`。

每个写入都会重新核对提交的 `recipient.userId`。上传和提交还要求提交处于可编辑状态；老师关闭学生附加资源时，上传会停止。已正式提交的作业应先撤回，再上传新文件。

上传工具依次准备本人资源目录、写入文件，再把文件关联到本人提交。文件存储名带有随机前缀，避免覆盖已有同名文件；Teams 显示名保留原文件名。上传不会自动提交作业。

如果文件已上传但关联失败，工具返回不确定结果，并在错误详情中提供已完成阶段和已上传文件标识。应先检查提交资源，避免重复上传。服务不自动删除可能已经用于提交的文件。

已提交作业再次调用提交工具时，返回 `alreadyApplied=true`。处于 `working` 状态的提交再次撤回时，也返回该标志。其他状态由本地检查和 Graph 共同决定，不根据令牌权限绕过学校规则。

## Outlook 事件

`create_outlook_event` 在绑定账号的主日历创建个人事件，不接受参加人列表，也不发送会议邀请。主题和起止时间为必填项，可附正文、地点及提醒分钟数。

起止时间使用带偏移的 ISO 8601，结束应晚于开始，范围最多跨 31 天。服务转为 UTC 后提交。`requestId` 同时作为 Graph 的 `transactionId`，用于避免重复创建。

## 请求去重与结果

每个写入都需要 UUID 格式的 `requestId`。同一次操作重试时，应使用相同 ID 和参数；修改参数或执行新的动作时，使用新的 ID。

写入记录按账号、动作和请求 ID 区分。成功响应可在服务重启后重复取得，不再请求上游。同一请求 ID 对应不同参数时，返回 `WRITE_REQUEST_CONFLICT`。上传文件的临时下载地址可更新，但文件 ID、名称和内容标识应保持一致。

同一作业的上传与提交不能同时运行。服务进程最多执行 4 个写入。记录最多保存 2000 项，新写入前清理 7 天前的记录。记录文件权限为 `0600`，保存请求摘要与结果元数据，不保存回答或文件内容参数。

请求已发出但结果无法确定时，服务返回 `WRITE_OUTCOME_UNKNOWN`，不自动重复写入。先使用只读工具检查作业、附件或日历状态，再决定是否以新请求 ID 执行。若发现服务重启前留下未完成记录，也采用相同规则。

写入后，服务清除对应平台的查询缓存。上游明确拒绝身份验证时，服务恢复登录后重试一次；网络超时或服务器错误不会触发业务写入自动重放。

# 微软授权与 Teams

微软授权独立于校宝登录和 ChatGPT 到 MCP 的 OAuth 授权。服务器取得微软授权后，直接读取 Microsoft Graph，不依赖 Giaoculator 或浏览器持续运行。

## 应用与权限

设备代码登录需要允许公共客户端设备代码流程的微软应用。学校租户还应允许该应用使用以下委托权限：

| 权限 | 用途 |
| --- | --- |
| `User.Read` | 核对绑定账号身份 |
| `EduRoster.ReadBasic` | 读取本人教育课程 |
| `EduAssignments.Read` | 读取作业、本人提交和评分结果 |
| `Calendars.Read` | 读取主日历 |
| `offline_access` | 获取刷新令牌 |

教育权限可能需要学校管理员批准。既有应用是否支持设备代码流程，应通过实际授权确认。不能只根据浏览器扩展可以登录，就判定该流程可用。

应用 ID 和租户 ID 可来自自己注册的应用，或已获准使用的既有应用。服务没有内置第三方应用 ID，也不自动注册应用、变更学校授权或复用浏览器扩展的回调地址。

默认登录申请上述只读权限。微软仍可能返回该应用已经取得的其他权限，包括写权限。只读工具只发送 GET 请求；独立写入工具按固定路径和所需权限执行操作。令牌只留在服务器，不返回给 MCP 客户端。

需要上传附件、提交／撤回作业或创建事件时，另外执行 `npm run microsoft:login -- --write`。该命令申请 `EduAssignments.ReadWrite`、`Calendars.ReadWrite` 和 `Files.ReadWrite`。学校或应用配置可能要求额外同意。缺少文件权限时，Teams 上传工具会在建立目录或上传文件前停止，已有只读工具仍可使用。

升级写权限时，命令核对新授权与既有绑定属于同一个微软账号。需要更换账号时，应先用普通登录命令显式重新绑定，再申请写权限。

## 从 SSH 登录

首次登录时，执行以下命令。把 `YOUR_APPLICATION_ID` 和 `YOUR_TENANT_ID` 替换为实际的应用 ID 和学校租户 ID。

```bash
npm run microsoft:login -- --client-id YOUR_APPLICATION_ID --tenant-id YOUR_TENANT_ID
```

也可在 `.env` 中设置 `MICROSOFT_CLIENT_ID` 和 `MICROSOFT_TENANT_ID`，再运行：

```bash
npm run microsoft:login
```

命令显示验证地址、设备码和过期时间。设备码只用于本次登录，不是访问令牌。

1. 用手机浏览器打开命令显示的微软验证地址。
2. 输入设备码。
3. 使用学校微软账号登录，核对应用和权限，完成所需的多重身份验证。
4. 等待终端显示身份验证成功。

命令在微软要求的间隔后轮询授权结果。收到 `slow_down` 时，命令增加轮询间隔。验证码过期、拒绝授权或学校策略阻止登录时，命令停止，不保存半完成的绑定。

服务先调用 `/me` 核对身份，再以原子替换方式保存 `secrets/microsoft.json`，权限为 `0600`。文件包含绑定账号 ID、应用 ID、租户 ID、访问令牌、刷新令牌、权限列表和过期时间，不包含微软密码。

后续重新登录可直接运行 `npm run microsoft:login`，命令会读取既有绑定的应用和租户配置。更换微软账号属于显式重新绑定。所有获授权的 MCP 客户端随后都会读取新绑定账号，因此只应把此个人服务授权给本人。

Docker Compose 把 `MICROSOFT_FILE` 固定为 `/app/secrets/microsoft.json`，并复用现有 `secrets` 绑定目录。终端命令与容器应使用同一个私有文件及系统用户。直接运行时，可用 `MICROSOFT_FILE` 指定其他私有路径。

## 自动刷新与身份

客户端在访问令牌即将过期或 Graph 返回 HTTP 401 时刷新令牌。并发查询共享同一次刷新。微软返回新的刷新令牌时，客户端保存新值；没有返回新值时，保留原值。

刷新会保留当前令牌已取得的作业、日历和文件写权限，不自动申请缺少的写权限。新增权限通过带 `--write` 的设备代码登录取得。

刷新后，客户端再次查询 `/me`，并与固定的账号 ID 比较。身份不同或刷新期间绑定发生变化时，客户端停止读取，不覆盖新绑定。客户端发现绑定文件变化后，清空旧账号缓存。

不可重试的刷新失败会阻止后续 5 分钟内的重复刷新，可重试失败的间隔为 30 秒。重新绑定会清除该等待状态。刷新令牌被撤销、学校要求重新验证或应用配置改变时，应重新运行登录命令。自动刷新不保证永久免登录。

校宝账号与微软账号分别绑定，服务不自动判断二者是否属于同一学生。微软工具可独立于校宝会话使用。现有 MCP 权限 `schoolis.read` 覆盖服务内所有只读工具，包括已绑定的微软账号。

## 数据范围

服务提供以下读取能力：

- 本人微软账号身份和教育课程。
- 指定课程的作业和作业详情，保留原始截止时间。
- 属于绑定账号的提交状态。
- 本人提交已公布的分数、评语和评分量表结果。
- 主日历事件及重复事件的实例。

Teams 列表没有隐式的最近 14 天筛选。微软列表使用游标分页；一页数据不代表全部课程或作业。继续分页时，应保持原有 ID、筛选条件及 `pageSize`。游标绑定账号与接口，有效期为 30 分钟。

评分工具先核对提交归属，再返回以 `published` 开头的结果字段，不返回草稿分数和评语。空结果不表示一定没有作业或评分，应结合分页状态及学校是否公布结果判断。

日历查询最多跨 31 天，输入时间应包含时区偏移，输出时间使用 UTC。`create_outlook_event` 可创建不含参加人的个人事件；当前不提供事件修改或删除。

具备 `schoolis.write` 和相应微软权限时，可上传附件到本人可编辑的提交，再单独提交或撤回作业。附件通过 SharePoint 驱动器上传，并关联为 Teams 提交资源。服务器使用唯一存储名避免覆盖同名文件，显示名保留原文件名。具体流程见[作业写入与文件上传](writes.md)。

工具不读取聊天或频道消息，不提供 SharePoint 文件下载。只读作业详情中的资源链接仍为元数据。微软返回的说明、评语和日历正文属于不可信业务文本，不能作为执行指令。
